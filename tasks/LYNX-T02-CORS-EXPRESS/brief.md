# Brief — LYNX-T02-CORS-EXPRESS
Status: propozycja kontraktu do prechecku Codexa; bez implementacji.
PRODUCT_TRUTH: `arch/spec.md` S1, S5, S6; `arch/FINDING_2026-10_AUDYT.md` BUG-EXPRESS-TOKEN-SCOPE + CORS wildcard.
OWNER_DECISION: brak; nie zmieniać tego, czy tryb Express może wypuścić niezamaskowaną osobę (osobne pytanie OWNERA).
Cel: obca witryna nie może przez przeglądarkę odczytać słownika i archiwum lokalnego backendu.
Zachowanie: token Express nadal dostępny dla lokalnego UI i uprawnia WYŁĄCZNIE do `POST /preview` (rzeczywiście używany przez Express: `App.tsx` → `MainLayout.tsx` → `Pseudonimizuj.tsx`) oraz `POST /preview-express` (istniejący endpoint niepodłączonego `ExpressModeScreen.tsx`). Każdy inny endpoint, w tym profil, eksport i archiwum, przy tym tokenie zwraca 401. Dodatkowo serwer weryfikuje nagłówek `Host`, niezależnie od CORS i obecności `Origin`: dopuszcza wyłącznie lokalne nazwy `127.0.0.1` i `localhost` dla portu 8765 (nagłówek wysyłany przez UI: `127.0.0.1:8765`); żądania skierowane przez obcą domenę, np. `Host: evil.example:8765`, mają zostać odrzucone 400 **zanim** dostaną `/express/token` lub dane. Bez wildcard, `testserver` w produkcji ani wyjątku dla żądania bez `Origin`. Wykorzystać istniejący middleware/`TrustedHostMiddleware`, bez nowego modułu; pamiętać, że wbudowany TrustedHost waliduje nazwę hosta, nie numer portu — jeśli kontrakt wymaga ścisłego portu, dopasować go osobno w tym samym ownerze. Zachowanie aktualnego UI Express pozostaje bez zmian; nie przełączać go teraz na inny pipeline. CORS dla UI Windows Tauri 2: w dev dozwolony dokładnie `http://localhost:1420` (konfiguracja `devUrl`), w wydaniu Windows oczekiwany `http://tauri.localhost` (Tauri 2, domyślny schemat, bez `useHttpsScheme`). Nie dopuszczać `*`, `null`, obcych domen, portów ani wzorca `localhost:*`. Żądania bez `Origin` nie otrzymują nagłówka `Access-Control-Allow-Origin`, ale nadal przechodzą zwykłe sprawdzenie tokenu; sam brak `Origin` nie daje dostępu. Przed końcowym PASS/merge T02 trzeba potwierdzić rzeczywiste nagłówki `Origin` i `Host` z działającego wydania Windows; przy rozbieżności zatrzymać dostawę i wrócić do Architekta, nie poszerzać listy bez dowodu. **Zależność T10-BUILD-TS:** obecnie release nie buduje się z powodu błędów TypeScript. Najpierw minimalna naprawa TS w osobnym T10 (bez ikon i bez dodawania jej do `TASK_SCOPE` T02), potem uruchomienie wydania i pomiar, dopiero wówczas finalny PASS T02. Implementacja oraz precheck T02 mogą przebiegać wcześniej; nie wolno zastępować pomiaru samą dokumentacją Tauri. Pełny token API zachowuje uprawnienia. Nieautoryzowana odmowa bez PII w odpowiedzi i bez nowych danych na dysku.
